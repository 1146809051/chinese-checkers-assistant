# 跳棋助手（网页版）设计文档

日期：2026-08-04
状态：已获用户确认

## 1. 目标

做一款辅助下跳棋的工具：手机浏览器打开页面，摄像头对准物理跳棋盘，用户点选自己的颜色，应用实时识别棋盘与棋子，算出当前回合最佳单步走法（含连跳完整路径），并把路径直接叠加画在摄像头画面上。

## 2. 已确认需求（来自用户访谈）

| 项目 | 决定 |
| --- | --- |
| 辅助程度 | 每回合算最佳单步：选哪颗子、走/跳到哪个位置、画完整连跳路径 |
| 识别方式 | 自动识别棋盘 + 自动识别棋子颜色，识别失败/不确定时有手动校正兜底 |
| 选色方式 | 点屏幕上的颜色圆点 |
| 规则 | 标准六角星棋盘、每角 10 颗、最多 6 人；可走相邻一格，或隔一颗子连跳（可连续跳） |
| 摄像头 | 手持晃动为主，需要持续追踪保持叠加稳定 |
| 交付形态 | 网页版（手机浏览器打开即用），非 APK |
| 部署 | GitHub Pages（用户有 GitHub 账号） |
| 开发环境 | 用户无 Android/本地构建需求，网页版免安装 |

## 3. 技术方案

- 纯静态网页，无服务器、无构建工具、不引前端框架。
- 图像处理使用 **OpenCV.js**（开源 JS 版 OpenCV，浏览器内运行）。
- 摄像头使用浏览器 `getUserMedia`（需 HTTPS 或 localhost 安全上下文）。
- 页面模块划分（每个模块独立、可通过接口交互）：
  - `camera.js` — 摄像头预览、分辨率/帧率配置
  - `board.js` — 棋盘检测（锚定）、透视变换、光流追踪
  - `marbles.js` — 121 个位置棋子颜色识别
  - `rules.js` — 跳棋规则引擎：邻接图、合法走法生成、连跳展开
  - `solver.js` — 走法评估启发式，输出最佳路径
  - `overlay.js` — 在视频上叠加棋盘、棋子标记、规划路径
  - `main.js` — UI 胶水、流程状态机

## 4. 识别与追踪（核心难点）

### 4.1 锚定
- 首次对准棋盘：自动识别六角星轮廓与三角网格确定棋盘区域；失败则引导用户手动点 4 个角点。
- 锚定定义「棋盘坐标 → 屏幕坐标」的透视变换（Homography），之后每帧沿用。

### 4.2 持续追踪（应对手持晃动）
- 锚定后提取棋盘区域特征点，每帧用光流（Lucas-Kanade）跟踪特征点移动，RANSAC 求解当前帧新的 Homography。
- 叠加内容（棋盘、棋子、路径）始终跟随棋盘在画面中的位置。
- 追踪丢失（如被手遮挡、移出画面）→ 暂停叠加，提示重新对准或重新锚定，禁止乱画。

### 4.3 棋子颜色识别
- 将棋盘区域透视矫正为规整俯视图，对 121 个位置逐一采样。
- 用颜色聚类（HSV 分割）+ 圆形检测判断「空 / 某颜色」。
- 置信度低的格子标白圈，进入校正模式由用户点选确定。
- 识别出的颜色集合自动生成底部选色圆点。

## 5. 走法规划

- 规则引擎：121 位置六邻接图。对每颗己方棋子：
  - 走一步：移到相邻空位。
  - 连跳：隔一颗子（任意颜色）跳到对称空位，可连续跳，递归展开所有跳链。
  - 一条完整走法 = 起点 + 经过点 + 终点。
- 评估启发式（solver）：
  - 每颗子到目标阵营距离的缩短量（推进得分）。
  - 落点开阔程度、是否进入死区。
  - 是否堵住己方后续棋子路线。
  - 连跳链做剪枝控制计算量，保证手机上毫秒级出结果。
- 输出：起点→终点完整路径，黄色虚线叠加。

## 6. 界面与流程

### 首次使用
打开页面 → 授权摄像头 → 对准棋盘 → 自动锚定（失败则手动点 4 角）→ 确认棋盘 → 点选自己颜色 → 进入主界面。

### 主界面
- 顶部状态条：识别状态（稳定/追踪中/丢失）、当前我方颜色、重新锚定按钮、切换摄像头按钮。
- 全屏摄像头 + 叠加层：棋盘轮廓、棋子位置标记、黄色规划路径。
- 底部：颜色圆点（来自识别结果）+ 「规划路线」大按钮。

### 校正模式
- 识别不确定的格子标白圈，点击设为「某颜色」或「空位」，确认后继续。

### 演示模式
- 内置虚拟棋盘画面当作摄像头输入，不摆真棋盘即可测试识别与走法，也方便学习体验。

## 7. 错误处理

- 摄像头权限被拒 → 显示开启权限指引。
- 非 HTTPS 环境 → 提示使用部署好的 HTTPS 地址。
- 锚定失败 → 引导手动点 4 角。
- 追踪丢失 → 暂停叠加、提示重新对准/重新锚定。
- 识别不确定 → 进入校正模式。
- 性能不足 → 提供画质/处理频率调节。

## 8. 测试

- 规则引擎与走法算法：在电脑上用 Node 跑单测，验证走法生成、连跳、启发式正确性。
- 识别与叠加：演示模式 + 电脑摄像头联调。
- 最终：真机手机浏览器过一遍主流程。

## 9. 部署

- 开发期：localhost（电脑摄像头调试）。
- 上线期：GitHub Pages 托管静态文件，手机浏览器通过 HTTPS 打开使用。

## 10. 范围外（本期不做）

- APK / 原生 App（网页版验证后再议）。
- 整盘长期策略分配（只做每回合最佳单步）。
- 语音选色。
- 对战统计、复盘等附加功能。

## 11. 未决问题

- 目标阵营：标准规则下每名玩家的目标是对面阵营；已确认为每回合最佳单步，评估时把「对面阵营」作为目标距离基准。
- 多人共用同一棋盘场景暂不考虑（默认单玩家使用）。
